# tools/ audit, 2026-08-08 (SALVAGED, PARTIAL)

Multi-agent audit of `tools/`, prompted by the user finding that the RC check
passed with the transmitter switched off. **The run was stopped early to save
usage**: 4 of 7 reviewers finished (66 raw findings, deduped to the list below),
and the adversarial verification pass completed only 8 of ~66 verdicts.

**STATUS OF EVERY ITEM BELOW: UNVERIFIED BY A SECOND OPINION AND UNFIXED.**
The finders cited ArduPilot/pymavlink source for most claims, and where they did
the claim is likely sound, but nothing here has been confirmed against hardware
or a real `.bin`, and no fix has been applied. Treat as a work list, not as
established fact. Re-running the (now cheaper) audit is TODO.

The recurring mistake across all of it is the one that started the audit:
**testing that a message exists rather than that the thing it represents is
true**, plus its cousin, **a printed verdict that never reaches the exit code**.

---

## CRITICAL

1. **`check_log.py` clipping detection is dead code.** ArduPilot 4.7 logs VIBE as
   `TimeUS,IMU,VibeX,VibeY,VibeZ,Clip` — one instance-tagged record per IMU with a
   single `Clip` field. `Clip0/Clip1/Clip2` is the pre-4.1 layout, so
   `getattr(msg,'Clip0',0)` returns 0 forever and the "any clipping" warning can
   never fire. Clipping is a documented STOP CONDITION.
2. **`check_log.py` pools all IMU instances into one VibeZ median.** VIBE is
   written per IMU; one bad IMU is diluted by the healthy ones. Worked example:
   IMU0 at 23, IMU1/2 at ~8 gives a pooled median ~8 and a PASS, while the EKF
   may be flying on IMU0. Gate must be per-instance, worst-instance-wins.
3. **`check_log.py` reads hover throttle from PARM**, which only carries the
   head-of-log value. Learned hover throttle never appears there (it is saved on
   disarm, not via the PARM path) — it is in `CTUN.ThH`. The >0.5 stop condition
   therefore never triggers on the learned value.
4. **`wiring_check.py --wiggle` can leave the dropper gate OPEN.** No
   confirmation (unlike the motor test), no `try/finally`, no retry, and the
   close command's ack is never checked. A lost ack over the radio or a Ctrl+C
   in the 1.5 s sleep leaves the gate open, and the run still prints PASS.
5. **`wiring_check.py` motor-test and wiggle results never reach `ok` or the
   exit code.** `ok` is finalised before either runs. Every motor can return
   FAILED and the script still prints `ALL WIRED CHECKS PASS` and exits 0.
6. **`bench.py setparam` accepts any `PARAM_VALUE` as confirmation** — no
   `param_id` match, no comparison of the echoed value to the requested one. A
   clamped, refused, or entirely unrelated param prints as success.
   `push_params.set_param` already does this correctly in the same repo.
7. **`push_params.py` uses the naive `wait_heartbeat()`** this repo documented as
   broken, and discards its return. With the ESP32 heartbeating first, or nothing
   connected, it prints `connected: sys 0 comp 0` and sends every write to
   broadcast. Should use `wait_autopilot()` and abort when it fails.

## HIGH

8. `check_log.py` **always exits 0**, including on GATE FAIL and on "no samples".
   `check_log.py x.BIN && proceed` clears a failing airframe.
9. `check_log.py` **throttle-gates the GPS check**, which excludes the arming
   window — precisely the C3 crash condition the check cites as its reason to
   exist. Arming happens at zero throttle.
10. `check_log.py` treats **a log with VIBE but no CTUN as a bench log** and exits
    clean; VIBE and CTUN are gated by different LOG_BITMASK bits, so a real
    flight with failing vibration can report "nothing to see".
11. `check_log.py` **MSG filter misses `Crash: Disarming` and `Potential Thrust
    Loss`** — the in-flight signature of the prop/motor failure mode this
    airframe has already suffered once.
12. `wiring_check.py` **judges on the last SYS_STATUS frame only**, and
    `all_satisfied()` breaks the loop the instant RC first reports healthy. An
    intermittently-failing receiver or compass passes on one good sample.
13. `wiring_check.py` **RING does not know about `RING_SENSOR_FITTED`**, so the
    deliberately-removed channels 2/3/4 are reported DEAD and a correctly
    configured ring always FAILs.
14. `wiring_check.py` **COMPASS prints "mag enabled+healthy" on the FAIL line** —
    the detail is chosen by `sys_status_seen`, not by the verdict.
15. `wiring_check.py` **RC health is meaningless when `FS_THR_ENABLE=0`**:
    ArduPilot only sets the radio-failsafe flag when throttle failsafe is
    enabled, so the transmitter-off bug returns silently if that param reverts.
16. `wiring_check.py` **early-exit and ESP32 verdict disagree**: with the ring
    refitted but `--expect-esp32` not passed, the loop can break at ~1.5 s and
    then print a false RING FAIL naming healthy sensors as dead.
17. `bench.py getparam` **prints whatever `PARAM_VALUE` arrives next**, labelled
    with the name you asked for.
18. `bench.py gps` **prints READY without checking `fix_type`** and on a single
    sample; a 2D fix with 11 sats and good HDOP reads as ready to arm.
19. `bench.py rng` **cannot detect the dropout it exists to detect**: upward
    DISTANCE_SENSOR frames reset the miss counter, and readings are printed with
    no range validation.
20. `bench.py failsafe` **instructs a transmitter-off on a possibly-armed
    aircraft** with no disarm check and no props warning; `FS_THR_ENABLE=1` makes
    that an RTL command.
21. `pull_params.py` **overwrites the "do not edit" calibration backup with a
    short fetch**, with only an informational count as warning.
22. `make_complete_params.py` **silently truncates non-REAL32 overrides** via
    `int(float(new))` while printing the untruncated value.

## MEDIUM / LOW

- `check_log.py`: Clip counters are cumulative since boot, so `max()` reports
  lifetime clips including pre-flight handling; report the in-window delta.
- `check_log.py`: ERR events printed as raw numbers, never fail the run, and
  include ArduPilot's own vibration failsafe (subsys 29).
- `check_log.py`: `if v and ...` discards a 0.00 V battery reading — the most
  alarming possible value — and the whole BATTERY section then vanishes.
- `check_log.py`: no GPS samples prints `worst sats None` with no warning.
- `wiring_check.py`: ring sectors scored on `!= 65535` only; a sensor stuck at
  0 cm counts as reporting (the TF-LUNA check twelve lines away does bounds-check).
- `wiring_check.py`: `send_and_ack` drains STATUSTEXT, discarding ArduPilot's
  stated reason for a refused motor test ("Motor Test: Safety switch").
- `wiring_check.py`: `enums['MAV_RESULT'][ack.result]` can raise KeyError mid
  motor test (no key 6 in this dialect) and kill the run between motors.
- `wiring_check.py`: `--motor-throttle` unbounded; a typo of 88 for 8 is accepted.
- `wiring_check.py`: `--wiggle N` unvalidated and unechoed; `--wiggle 14` (the
  superseded channel) acks ACCEPTED and moves nothing.
- `wiring_check.py`: TF-LUNA failure detail never mentions the out-of-range
  reading that caused it, and the "0 =" hint contradicts a visible nonzero count.
- `wiring_check.py`: FC passes on ONE heartbeat though the file documents a
  two-heartbeat rule; SiK hint hardcodes `/dev/ttyUSB0`; docstring says the
  `--seconds` default is 25 when it is 12.
- `push_params.py`: docstring promises a final readback pass and table that does
  not exist; silently drops any setup line without a comma; prints "All
  parameters verified" when zero were parsed; no nonzero exit on refusals.
- `pull_params.py`: comment claims targeted index retries, code re-sends the full
  list; `round(v, 6)` breaks float32 round-trip for small calibration values.
- `make_complete_params.py`: `rstrip('0')` mangles integer "before" values
  (BATT_CAPACITY 3300 prints as 33).
